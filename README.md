# MetalFlow

Приложение на **Django 5.2 LTS + Django Templates** для автоматизации рабочей книги учёта металла. Интерфейс на русском и узбекском (латиница), без React и внешних CDN. SQLite, серверные формы, локальные CSS и JavaScript.

## Быстрый запуск

Требуется Python 3.10+.

```bash
git clone https://github.com/Alirizo7/excel-crm.git
cd excel-crm
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 127.0.0.1:8765
```

Открыть [MetalFlow](http://127.0.0.1:8765/).

Для повторного запуска достаточно `./run.sh`. При первом запуске создаётся пустая база; рабочие данные загружаются через импорт Excel.

Первый импорт в новой базе — через страницу **Импорт Excel**, либо:

```bash
python manage.py import_workbook /absolute/path/01.09.2026.xlsx
# Только проверка, без включения данных в учёт:
python manage.py import_workbook /absolute/path/01.09.2026.xlsx --preview
```

## Возможности

- Сводка с приходом, расходом, сальдо, отгруженным весом, графиком по месяцам и категориями расходов.
- Журнал денег: поиск, фильтры по датам, типу и категории, карточка каждой операции.
- Поставки: приёмка и отгрузка, машины, контрагенты, вес, скидка, цена, автоматическая стоимость.
- Добавление записей, редактирование импортированных операций и поставок, удаление и восстановление, история изменений.
- Долги, карточки контрагентов, полные и частичные погашения, отмена оплаты, сроки, просрочки и сводная статистика.
- Импорт с предпросмотром, проверкой структуры и значений, подтверждением, историей и защитой от повторов.
- Просмотр всех исходных листов с номерами строк, поиском и раскрытием формул; скачивание неизменённого оригинала.
- Excel-экспорт операций, поставок, взаиморасчётов и сводного отчёта. Пустые шаблоны с выпадающими списками.
- Адаптивная навигация, расчёт поставки в форме, доступные подписи полей, серверная проверка ошибок.
- Страница входа, Django Admin и журнал действий.

## Как читается предоставленный Excel

| Источник | Назначение |
| --- | --- |
| `Приход-Расход` | Единственный источник основного денежного журнала: A–C расход, D–F приход. Строки с 4-й. |
| `тура ака` | Отгрузки: F брутто, G тара, I скидка, K цена. |
| `дафтарча` | Приёмка по повторяющимся блокам. Контрагент берётся из K строки заголовка блока. F и G — два веса, используемые в исходной формуле вычитания. |
| `Чугун` | Приёмка: H брутто, I второй вес (тара по смыслу формулы), K скидка, M цена. |
| `Кунлик` | Сводка взаиморасчётов: D − E. Исходные знаки сохранены. |
| `тонн`, `Хитой`, `Чермт Бонус`, `Рахим`, `Каракул`, `тогом`, `Гостиница`, `Бонусча` | Сохраняются для просмотра и скачивания. В основной денежный журнал повторно не включаются. |

Даты разбираются из Excel-дат, `01,09,26`, `01.09.2026`, ISO и аналогичных записей. Пустые даты наследуются **внутри своей колонки и блока**. Начало каждого блока `дафтарча` сбрасывает дату. Неизвестные даты не подменяются датой импорта или другой колонкой. Отчёты с периодом исключают записи без даты.

Веса хранятся в килограммах; сводка переводит их в тонны. Расчёт:

```text
нетто = брутто − тара
чистый вес = нетто × (1 − скидка / 100)
стоимость = чистый вес до округления × цена за кг
```

Расчёты используют Decimal. Вес сохраняется до 0,001 кг, деньги — до 0,01 UZS, округление Decimal ROUND_HALF_EVEN. Отрицательные денежные суммы остаются сторно в исходном типе операции. **Сальдо журнала не равно прибыли или наличным в кассе**: в источнике есть начальный долг.

Категории операций автоматически предлагаются по словам в назначении платежа. Это классификация приложения, а не отдельный справочник из Excel. Импортированные и ручные записи редактируются в приложении. Исходные строки, ID и оригинальный файл сохраняются. История показывает значения до и после изменения. Удаление исключает запись из итогов и экспорта; восстановление доступно, пока запись не архивирована заменой снимка.

### Проверка книги

После загрузки приложение показывает число распознанных строк, итоги операций, веса и замечания. Ошибки Excel, записи без даты, дополнительные корректировки и смешанные валюты видны на странице проверки. Рабочие суммы, загруженные файлы и база данных в репозиторий не включаются.

## Два режима импорта

**Полная рабочая книга**: обязательны знакомые листы `Приход-Расход`, `тура ака`, `Кунлик` и их колонки. После подтверждения прежние операции и поставки архивируются. Если они изменены в приложении, нужна отметка о замене правок. Новая книга включается атомарно; ручные записи и отдельные шаблоны сохраняются. Для долгов доступны два режима: сохранить текущие долги и не применять новые строки «Кунлик» либо принять остатки из новой книги, сохранив старые долги и оплаты в архиве. При замене новые суммы трактуются как актуальный остаток: прошлые оплаты повторно из них не вычитаются.

**Шаблон «Операции» или «Поставки»**: один лист с колонками скачанного шаблона. Добавляются новые строки. ID можно оставить пустым; приложение вычислит стабильный ID из строки. Одинаковый ID пропускается, существующее значение не переписывается. Экспорт этих двух журналов пригоден для обратной загрузки, включая дополнительные вычисленные колонки поставок.

Файл целиком проверяется по SHA-256: переименование не создаёт дубликат. Обычные ошибки шаблона блокируют весь импорт. Неподдерживаемая/ошибочная формула суммы денежной операции тоже блокирует импорт. Замечания во вспомогательных ячейках показаны отдельно.

Сводный отчёт предназначен для чтения и не является форматом обратного импорта. Оригинал сохраняется **байт в байт**, без добавления новых записей из приложения.

**Границы**: приложение ориентировано на одну рабочую книгу / один бизнес, не на несколько организаций. Совпадение ручной записи и строки будущего снимка по смыслу автоматически не определяется: ручную копию нужно исключить, если её внесли в Excel. Изменение колонок требует обновления адаптера. Вспомогательные бизнес-расчёты и распределение прибыли доступны как снимок исходных листов, отдельные редакторы для них не реализованы.

## Формулы и безопасность файлов

Используются сохранённые результаты Excel. При отсутствии результата поддержан ограниченный расчёт арифметики, ссылок и `SUM` диапазона. `eval()` не используется; функции, макросы, внешние ссылки и инструкции из ячеек не исполняются. Неподдерживаемые формулы нужно пересчитать в Excel перед загрузкой. Импорт не выдаёт наличие кэша за доказательство актуальности всех формул.

Ограничения: `.xlsx`, до 10 МБ, до 60 МБ после распаковки, до 30 листов, 12 000 строк и 64 колонок на лист; суммарная прямоугольная область до 750 000 ячеек. Загруженные файлы не публикуются через `MEDIA_URL`; оригиналы выдаются защищённым Django-view. Текстовые значения в экспорте принудительно сохраняются текстом, включая строки с `=`.

## Доступ и развёртывание

По умолчанию включён локальный режим: вход не требуется **только для запросов с loopback-адреса** при `DEBUG=1`. Сервер запускается на `127.0.0.1`. Запросы не с loopback требуют авторизации. В режиме `DEBUG=0` локальный обход входа отключён.

Чтобы проверить вход локально:

```bash
python manage.py createsuperuser
LOCAL_WORKSPACE=0 python manage.py runserver 127.0.0.1:8765
```

Для сервера задайте переменные окружения из `.env.example`. `run.sh` читает локальный `.env`; при запуске Gunicorn переменные должны быть переданы самим окружением сервиса. Обязательны секретный ключ, допустимые хосты, `DJANGO_DEBUG=0` и HTTPS. Затем:

```bash
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py createsuperuser
gunicorn config.wsgi:application --bind 127.0.0.1:8765 --workers 2 --timeout 120
```

Reverse proxy завершает HTTPS и передаёт запросы приложению. Настройки доверия к proxy следует задать под конкретную конфигурацию; произвольные заголовки `X-Forwarded-*` не доверяются по умолчанию. Все авторизованные пользователи имеют доступ к общему учёту. Django Admin требует staff-доступа. Перед публикацией нужно настроить сервер, TLS, резервное копирование базы и `media/`. Публикация исходного кода на GitHub сама по себе не запускает Django-сервер.

## Долги и погашения

Раздел «Взаиморасчёты» показывает остатки с учётом оплат, задолженности в обе стороны, просрочки и погашенные обязательства. Нажатие на долг открывает его карточку; ссылка «Все долги контрагента» показывает общую историю по этому человеку. Новые долги можно добавлять вручную и задавать основание и срок оплаты. Названия контрагентов объединяются по точному нормализованному имени без учёта регистра и лишних пробелов; похожие имена автоматически не сливаются.

Оплата содержит дату, сумму и примечание. Она уменьшает остаток; переплата, нулевая сумма и будущая дата отклоняются. Отмена требует причину, возвращает сумму в остаток и сохраняет историю. Долг с действующими оплатами нельзя удалить, уменьшить ниже погашенной суммы или перенести на другого контрагента/сторону. Погашения учитываются в отдельном реестре; денежный журнал ведётся независимо, чтобы не создавать дубли существующих операций Excel. Это регистрация факта оплаты, а не банковский перевод.

При повторном импорте можно сохранить текущий реестр долгов целиком или заменить импортированные долги актуальными остатками «Кунлик». Во втором случае новая книга должна уже учитывать совершённые оплаты. Прошлые оплаты остаются в истории контрагента и в сумме погашений за всё время. Ручные долги сохраняются при обоих режимах. Архивные оплаты доступны только для просмотра.

Все изменения финансовых записей используют транзакцию с общей строкой блокировки рабочего пространства. Версии записей защищают от сохранения устаревшей формы; уникальный ключ отправки защищает погашение от дублирования. Учётные данные и история в Django Admin доступны только для просмотра — изменения выполняются через рабочие формы и сервисы.

Миграции автоматически создают карточки существующих контрагентов, не меняя исходные суммы. Для CLI-импорта доступны `--debt-policy keep|replace` и `--replace-local-changes`. История изменений хранится полностью; карточка показывает последние 50 событий. Экспорт взаиморасчётов содержит актуальные остатки и отдельный лист погашений; сводный отчёт содержит пять листов.

## Проверки

```bash
python manage.py check
python manage.py test
WORKBOOK_PATH=/absolute/path/01.09.2026.xlsx python manage.py test ledger.tests.SuppliedWorkbookTests
```

Тесты проверяют сверку с предоставленным файлом, отрицательные суммы, формулы веса, независимое наследование дат, валидацию, повторные загрузки, замену снимка, сохранение ручных записей, обратный импорт экспорта, защиту от формул в тексте, страницы, фильтры, вход и CSRF. При отсутствии исходного файла тест его сверки пропускается; остальные тесты создают свои небольшие книги во временном каталоге.

## Структура

```text
config/                     настройки Django, URL, WSGI
ledger/models.py            операции, поставки, снимки, источники
ledger/services/importing.py адаптеры Excel и атомарный импорт
ledger/services/exporting.py генерация XLSX в Python
ledger/forms.py              проверка форм
ledger/views.py              сводки, поиск, импорт и выгрузка
templates/ledger/            серверные Django-шаблоны
static/                     CSS, JavaScript, локальная иконка
ledger/tests.py              проверки импорта и HTTP
ledger/test_debts.py         долги, оплаты, аудит, повторный импорт
ledger/test_i18n.py          переключение языка и обратный импорт
```

`db.sqlite3`, `media/`, `.env` и виртуальное окружение исключены из Git. Исходный пользовательский Excel не включается в репозиторий.

## Языки интерфейса и читаемость

Переключатель **RU / O‘Z** в верхней панели и на странице входа выбирает русский или узбекский язык (латиница). Выбор хранится в браузере в течение года; текущая страница и фильтры сохраняются. Переведены меню, формы, графики, подсказки и сообщения проверки Excel, включая ранее загруженные файлы.

Названия контрагентов, исходные ячейки и назначения платежей отображаются как в файле. Формат обмена Excel остаётся единым: названия листов, заголовки и значения типов не зависят от языка интерфейса, поэтому экспорт можно импортировать обратно.

Основные тексты, таблицы и формы используют увеличенный шрифт и более тёмные цвета. На узких экранах карточки перестраиваются в одну колонку, таблицы прокручиваются внутри блока, а подписи графиков сохраняют читаемый размер.

Переводы: `locale/uz/LC_MESSAGES/django.po`; готовый каталог `django.mo` включён в проект. Для изменения переводов нужен GNU gettext:

```bash
.venv/bin/python manage.py makemessages -l uz --no-wrap --ignore=.venv --ignore=media --ignore=staticfiles --ignore=.runtime
.venv/bin/python manage.py compilemessages -l uz --ignore=.venv
```

Проверки переключения языка, форм, сохранения исходных данных и совместимости Excel находятся в `ledger/test_i18n.py`.
