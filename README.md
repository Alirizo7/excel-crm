# MetalFlow CRM

MetalFlow — Django CRM для компаний, которые ведут денежные операции, поставки металла и долги в Excel. Клиент загружает существующий файл один раз, проверяет найденные данные и продолжает ежедневную работу через обычные страницы CRM.

Встроенного Excel-редактора в проекте нет. Исходный файл хранится для истории и повторной сверки, а новые операции, поставки, долги и погашения создаются в приложении.

## Возможности

- отдельное рабочее пространство и отдельные данные для каждой компании;
- самостоятельная регистрация владельца компании;
- импорт исходной книги `.xlsx` с предварительной проверкой;
- денежный журнал: приход, расход, поиск, фильтры, редактирование и удаление;
- поставки: брутто, тара, скидка, чистый вес и стоимость;
- долги: кто должен, остаток, срок оплаты, погашения и отмена погашения;
- обзор основных показателей и отчёты в Excel;
- русский и узбекский интерфейс;
- журнал изменений для рабочих записей.

## Быстрый запуск

Требуется Python 3.10 или новее. Node.js не нужен.

```bash
cp .env.example .env
./run.sh
```

Откройте <http://127.0.0.1:8765/>.

При первом запуске миграции создают администратора:

- логин: `admin`
- пароль: `admin123`

Этот аккаунт предназначен для локального запуска. Для нового клиента на странице входа нажмите **Создать компанию**: приложение создаст отдельное пустое пространство и предложит загрузить его Excel.

`run.sh` не добавляет демонстрационные данные автоматически. Поэтому новый клиент никогда не получает базу другого клиента.

## Ручной запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver 127.0.0.1:8765
```

## Рабочий сценарий клиента

1. Создать компанию и данные для входа.
2. Загрузить текущий `.xlsx` размером до 10 МБ.
3. Посмотреть результат проверки и исправить ошибки в исходном файле, если они найдены.
4. Подтвердить перенос.
5. Работать на страницах **Обзор**, **Деньги**, **Поставки** и **Долги**.
6. При необходимости загрузить новый снимок исходной книги через пункт **Загрузить Excel**. Перед заменой приложение показывает влияние обновления и сохраняет старый файл в истории.

Поддерживается исходная рабочая книга с листами `Приход-Расход`, `тура ака`, `Кунлик`, а также экспортированные MetalFlow файлы `Операции` и `Поставки`.

## Демо-набор

Готовый снимок первого клиента оставлен только для разработки и демонстрации. Он устанавливается вручную в пустую базу:

```bash
.venv/bin/python manage.py bootstrap_workspace
```

Команда не запускается автоматически и отказывается перезаписывать существующие данные.

## Проверки

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test
```

## Настройки

Основные переменные находятся в `.env.example`:

- `DJANGO_DEBUG=0` для production;
- `DJANGO_SECRET_KEY` — уникальный секрет;
- `DJANGO_ALLOWED_HOSTS` — домены приложения;
- `DJANGO_HTTPS=1` — безопасные cookies и перенаправление на HTTPS;
- `PORT` — порт `run.sh`, по умолчанию `8765`;
- `DJANGO_DB_PATH` — путь к SQLite;
- `DJANGO_MEDIA_ROOT` — каталог загруженных файлов.

Для production запускайте Django через WSGI-сервер, например:

```bash
gunicorn config.wsgi:application
```

Загруженные Excel-файлы находятся в `MEDIA_ROOT` и не публикуются через Django. Резервная копия должна включать SQLite и каталог `media`.
